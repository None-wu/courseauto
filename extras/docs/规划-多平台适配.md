# 多平台适配规划：学习通 / 智慧树（知到）/ 雨课堂

> 状态：**已实施(P0-P3 的视频/弹题部分,2026-11-04)**——内核+适配层重构完成,智慧树/雨课堂 MVP 已在各自模拟页跑通端到端;测验/考试与多模态习题仍按本规划待实施
> 目标：把当前只服务学习通的脚本，改成「一套内核 + 多平台适配层」，让同一份面板、同一套 AI 答题链路服务三个平台。

---

## 1. 先给结论

**可行，但三件事必须先说清楚：**

1. **代码本身不是障碍。** 1965 行里真正与学习通绑定的只有约 15 处（选择器 + 两个平台全局函数），其余（面板、日志、配置、AI 三通道、答案解析、字体解密、富文本回读、拟人化、上报）都是平台无关的，抽出来就能复用。
2. **真正的成本在"平台契约"上，而不在代码量。** 智慧树是 hash 路由 SPA、测验在另一个域名；雨课堂是一页一视频 + 强后台暂停 + 服务端记录进度。这三套契约差异极大，等于要写三套"任务驱动"，不是加几个选择器的事。
3. **我看不到你登录后的真实页面。** 选择器只能基于真实 DOM 快照来写，凭记忆写出来的适配器必然是"看起来能跑、实际点不中"。所以路线第一步不是写代码，是**先做快照采集**（见 §5）。

## 3. 目标架构

```
userscripts/
├── core.js            # 平台无关内核（发布时内联进单文件）
│   ├── 面板 / 配置 / 日志 / 统计 / 上报
│   ├── 答题流水线：题干提取 → 答案获取(题库/API/网页AI) → 解析 → 匹配 → 作答 → 校验
│   ├── 字体解密、富文本写入、拟人化、自动更新
│   └── 适配层调用协议（下面的 adapter 接口）
└── adapters/
    ├── chaoxing.js    # 学习通（把现有逻辑迁进来）
    ├── zhihuishu.js   # 智慧树 / 知到
    └── yuketang.js    # 雨课堂
```

### 适配器接口（草案）

```js
const adapter = {
  id: 'zhihuishu',
  name: '智慧树',
  match: [/^https?:\/\/studyh5\.zhihuishu\.com\//, /:\/\/study\.zhihuishu\.com\//],

  // 1. 页面类型：课程列表 / 播放页 / 测验页 / 不相关
  pageKind(),

  // 2. 列出本章所有任务点（顺序即执行顺序）
  //    [{ id, kind:'video'|'audio'|'doc'|'quiz', el, done:boolean, label }]
  listTasks(),

  // 3. 执行单个任务；内部可回调内核的 answerQuestion()
  async runTask(task, ctx),

  // 4. 跳转到下一个任务/下一节，返回是否还有后续
  async next(),

  // 5. 把平台题目 DOM 归一成内核的题目对象
  //    { type:'single'|'multi'|'judge'|'fill'|'short', stem, options[], el }
  extractQuestion(el),

  // 6. 把答案写进平台控件（返回是否写入成功，内核负责回读校验）
  applyAnswer(q, answers),

  // 7. 提交 / 交卷（可返回 { submitted, score? })
  async submit(ctx),
};
```

内核只认这 7 个方法，平台细节全在 adapter 里。这样以后新增一个平台 = 加一个文件，不动内核。

## 4. 两个新平台的差异与难点

### 4.1 智慧树 / 知到（zhihuishu.com）

| 项 | 情况 | 影响 |
|----|------|------|
| 页面形态 | `studyh5.zhihuishu.com/videoStudy.html#/studyVideo?...`，**hash 路由 SPA**，切视频不刷新页面 | 不能靠 `#iframe` URL 变化驱动，要监听 hash 变化 + 任务点状态 |
| 任务点 | 侧边栏目录树，视频/文档/测验混排，完成状态在树节点上 | `listTasks()` 从目录树取，比学习通的图标好写 |
| 弹题 | 播放中途弹窗，答题后才继续 | 复用 `tryPopupQuiz`，换选择器 |
| 视频完成判定 | **平台按累计时长校验**，倍速过高可能不计入（社区脚本普遍用 1.25x、到 91% 才切） | 必须做"实际记录进度"校验，不能只看 `ended` |
| 章节测验 | 在独立域名 `examh5.zhihuishu.com` / `onlineexamh5new.zhihuishu.com` | 需要单独的 adapter 入口 + 交卷逻辑 |
| 加密字体 | 部分课程题目用自定义字体混淆 | 现有 Canvas 解密可直接复用（这是我们相对其他脚本的优势） |
| 学习习惯分 | 一次刷完会丢习惯分，平台有"每日学习时长"统计 | 建议默认开"每日上限"，与现有配置项对齐 |

**难度：中等。** 视频页相对规整，主要工作量在 SPA 路由驱动和完成度校验。

### 4.2 雨课堂（yuketang.cn）

| 项 | 情况 | 影响 |
|----|------|------|
| 页面形态 | 有 **V2 / Pro / 学习空间（`/ai-workspace/lms-graph`）** 三套前端并存 | 需要三套选择器，或只支持最新一套 |
| 视频 | **一页一视频**，播完要自己跳下一个 | `next()` 必须实现跨页跳转（URL 导航），比学习通难 |
| 后台暂停 | 页面失焦即暂停，平台脚本主动 `pause()` | 需要"always-on-focus"式拦截（劫持 `visibilitychange` / `pause`）——这是社区脚本的核心卖点 |
| 进度判定 | **服务端记录真实进度**，进度条跑满也可能不算完成 | 必须读平台记录的进度接口/节点状态，不能只看 video 时间 |
| 习题 / 讨论 | 独立单元，习题常含图片、公式（需 OCR 或截图问答） | 文本通道不够，得启用"题目渲染成图 + 多模态 AI" |
| 风控 | 有验证码/行为检测，社区脚本会"检测到验证就停" | 内核需要加"检测到风控立即停手"的熔断 |

**难度：最高。** 主要卡在"一页一视频的跨页编排"和"服务端进度校验"。

## 5. 路线：五个阶段

### P0 · 架构抽离（不改行为，1 个阶段完成）
- 把 L1943 的 `main()` 改成适配器注册表；把 7 个接口从现有代码里抽成 `chaoxing` adapter
- 输出仍是**单文件油猴脚本**（构建期用 `build.mjs` 把 core + adapters 内联，保持"一个文件"的安装体验）
- 验收：`npm test` 11/11 + `npm run test:webai` 13/13 全绿，界面与功能零变化
- 风险：低。这是纯重构，有现成端到端测试兜底

### P1 · 快照采集器（写真实适配器的前提）
- 新增 `local/probe.html` + 脚本内 `CX_PROBE` 模式：在任意平台页面导出
  `{ url, title, iframes, 任务节点树, 题目节点 outerHTML, 关键接口 }` 到本地 `/api/probe`
- 你在智慧树、雨课堂各打开几个典型页面，我据此写选择器
- 验收：`local/probe/zhihuishu-*.json`、`yuketang-*.json` 落盘，能据此复刻 mock 页面

### P2 · 智慧树 MVP（视频 + 弹题 + 切视频）
- 只做：目录树任务枚举、视频静音倍速、弹题作答、播放完自动下一个、进度校验
- 不做：章节测验、考试
- 验收：本地 mock 复刻智慧树视频页，端到端断言"看完 2 个视频 + 答对 2 道弹题 + 自动切换"

### P3 · 智慧树测验/考试 + 雨课堂 MVP
- 智慧树：测验页 adapter（答题 + 交卷 + 正确率门槛）
- 雨课堂：视频播放 + 后台保活 + 连播 + 进度校验
- 验收：各自 mock 场景跑通；风控检测分支有单测

### P4 · 雨课堂习题/讨论 + 多模态
- 题目渲染成图（SVG foreignObject）→ 多模态 AI 问答；讨论区文本生成
- 验收：图片题能从"渲染 → 提问 → 回填"闭环

### P5 · 统一体验
- 面板显示当前平台徽标；配置分"通用 / 平台专属"两栏
- 三个平台共用一份题目记录与题库导出

**相对工作量：** P0 ≈ 15%、P1 ≈ 10%、P2 ≈ 25%、P3 ≈ 25%、P4 ≈ 20%、P5 ≈ 5%。

## 6. 风险与长期成本

| 风险 | 说明 | 缓解 |
|------|------|------|
| 维护成本 ×3 | 三套选择器 = 三倍改版冲击 | 适配器隔离 + 选择器集中成常量表 + mock 回归 |
| 平台改版静默失效 | 选择器失配的表现是"没反应"，不是报错 | 每个 adapter 加 `selfCheck()`，开页面先自检并明确提示"未匹配到任务节点" |
| 风控 | 雨课堂有验证码/行为检测；智慧树有学习习惯分 | 内核加熔断：检测到验证码/异常直接停手并提示；默认原速 + 每日上限 |
| 合规 | 三个平台条款均禁止代刷 | 保持现有免责声明；不提供"考试代考"默认开关 |
| 账号风险 | 多平台同时挂机容易被关联 | 建议单开窗口、串行使用 |

## 7. 已确认的决策（2026-11-04）

| # | 决策 | 影响 |
|---|------|------|
| 1 | **两个平台都做**，按「智慧树 → 雨课堂」顺序推进 | 智慧树链路规整，先跑通可以验证适配层抽象是否站得住，再攻雨课堂的硬骨头 |
| 2 | 自动化边界：**视频 + 弹题 + 章节测验自动提交**；讨论区**只生成草稿、不自动发送** | 讨论区做成「填入编辑框 → 面板出现『发送』按钮 → 用户点一下才提交」，保留人工闸门 |
| 3 | 交付形态：**单文件内联**，安装体验不变 | 源码拆分到 `src/`，构建时打包成单个 `.user.js`；产物文件名保持 `xuexitong-autostudy.user.js`，`@updateURL` 不断链 |

### 3.1 讨论区的"半自动"设计（决策 2 落地方式）

```
AI 生成回复 → 写入平台编辑框（可编辑） → 面板高亮「待发送：xxx」
   → 用户点「发送」→ 提交；点「改写」→ 重新生成；不理它 → 超时放弃，不发送
```

这样既省了打字，又不越过"未经确认代发"这条线——平台的行为检测对"自动提交讨论"最敏感。

### 3.2 单文件内联的构建方案（决策 3 落地方式）

```
src/
├── core/
│   ├── panel.js        面板 / 配置 / 日志 / 统计
│   ├── answer.js       题目模型 / 答案匹配 / AI 三通道 / 网页 AI 桥
│   ├── text.js         富文本写入 / 回读校验 / 字体解密
│   ├── guard.js        拟人化 / 风控熔断 / 每日上限 / 上报
│   └── main.js         适配器注册表 + 启动
├── adapters/
│   ├── chaoxing.js
│   ├── zhihuishu.js
│   └── yuketang.js
└── meta.txt            UserScript 元数据块
        ↓  node tools/build.mjs
userscripts/xuexitong-autostudy.user.js   （单文件，含全部 adapter）
```

- 每个文件是 IIFE 包，构建时按顺序拼接，共用一个 `CX` 命名空间，不引入打包器（保持零依赖）
- `@match` 追加三个平台的域名；`@name` 改为「网课助手 · 学习通/智慧树/雨课堂」，文件名不变以避免更新链断
- `npm run build` 产出 + `npm run check` 做语法检查与体积对比（超 300 KB 就拆分按需加载）

## 9. 仍然存在的风险（决策不改变这些）

- **维护成本 ×3**：三套选择器，任何一次平台改版都要单独跟。缓解：选择器集中成常量表 + 每个 adapter 的 `selfCheck()` 失配即明确报错。
- **我看不到登录后的真实页面**：P1 采集器不是可选项，是写适配器的前置条件。
- **合规**：三个平台条款均禁止代刷，风控后果由使用者承担。脚本不做"考试代考"默认开关，测验自动提交保留 60% 正确率门槛。
